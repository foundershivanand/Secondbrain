# The 8 Foundational Markdown Docs for Spec-Driven Vibe Coding

## Core Idea

Before writing code with AI or LLM coding assistants ('vibe coding'), establish a comprehensive 8-document repository blueprint (specs, architecture, design system, and agent rules) to provide full context and prevent AI hallucinations or architectural drift.

## Key Information

- 8 Critical Documentation Files for AI Projects: 1) PRD.md (Product Requirements Document), 2) DESIGN_SYSTEM.md (visual guidelines, tokens, UI states), 3) ARCHITECTURE.md (system flow, technical stack, boundaries), 4) DATABASE.md (schemas, relations, migrations), 5) SECURITY.md (auth, RBAC, data protection), 6) CODE_STYLE.md (linting, naming conventions, conventions), 7) TESTING.md (test strategy, coverage, suites), 8) AGENTS.md (agent roles, constraints, context prompt rules).
- DESIGN_SYSTEM.md breakdown includes: Design direction, Color palette with hex codes, Typography scale, Spacing tokens, Border radii, Component specs, UI states (empty/loading/error), Responsive breakpoints, and Accessibility rules.
- Methodology shifts AI programming from ad-hoc prompt-and-pray 'vibe coding' to rigorous spec-driven development (SDD).

## Insights

- The evolution of 'vibe coding' naturally converges back to software engineering discipline: the higher the AI autonomy, the more precise the upfront written constraints must be.
- Markdown files in repository root or `/docs` serve as persistent LLM system prompts and context grounding for tools like Cursor, Claude Code, and Copilot Workspace.
